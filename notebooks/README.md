# SENSE — Notebooks Index

Notebooks are generated by `scripts/_make_*.py` and executed in place with
`jupyter nbconvert --to notebook --execute --inplace`. They read artefacts
produced by the training and evaluation scripts; they never train or evaluate a
model themselves.

| Notebook | Status | Contents |
|---|---|---|
| `00_data_exploration.ipynb` | Complete | Dataset exploration, class and scenario distribution, stereo-pair visual QA |
| `01_preprocessing.ipynb` | Complete | Preprocessing and augmentation visual QA, enhancement comparison |
| `02_dataset_split_validation.ipynb` | Complete | Split validation, per-class distribution check, leakage check |
| `03_baseline_experiment_analysis.ipynb` | Complete | Single-image ResNet-18 baseline: training and validation curves, checkpoint selection, validation summary, test class distribution, confusion matrix, per-class metrics, most frequent confusions |
| `04_control_experiment_analysis.ipynb` | Complete | Backbone-matched control at the selected recipe: the same seven sections as `03`, applied to the control arm |
| `05_hyperparameter_analysis.ipynb` | Complete | Configuration sweep, learning-rate response, early-stopping behaviour, selected-model training curves |
| `06_ablation_study.ipynb` | Not started | Enhancement, stereo, and text-guidance ablation analysis. Blocked: no ablation arm has been trained |
| `07_final_evaluation.ipynb` | Complete | Standard test partition for all three arms: provenance, composition, selected-model detail, three-arm matrices, difference heat maps, headline and per-class comparisons |
| `08_robustness_analysis.ipynb` | Not started | Leave-one-scenario-out difficulty ranking and statistical analysis. Blocked: no LOSO fold has been run |

## Reading order

`00` → `01` → `02` describe the data. `03`, `04`, and `05` describe the three
modelled arms and the configuration study. `07` is the comparison: it reads the
artefacts of all three arms and reports the standard test partition once. `06`
and `08` depend on evaluations that do not exist yet.

`03` and `04` are generated by one script (`scripts/_make_arm_notebook.py`) from
one code path, so the two arms are analysed by identical code and cannot drift
apart. `07` is generated by `scripts/_make_final_evaluation_notebook.py`.

## Rules

- A notebook reads only artefacts that another step produced. No notebook
  contains pipeline logic, and no notebook writes to `runs/`.
- Metric definitions live in one place in the source tree; notebooks import
  them rather than reimplementing them.
- The standard test partition is read once. No notebook re-selects a model on it.
- A per-arm notebook measures its own arm. Comparisons between arms belong to
  `07`, and the interpretation rule behind them is stated there.
